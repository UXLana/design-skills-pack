# Async intake form

Read this only when the user asks for an intake form to send out. Paste the fields into any form tool (Google Forms, Microsoft Forms, Typeform). The fields mirror the guided question set in SKILL.md, so responses drop straight into synthesis mode.

Mark the starred fields required; they match the required sections in guided mode. Leave the rest optional so the form stays quick to fill in.

```
PROJECT BASICS
1. Project/feature name *
2. What initiated this request? (Customer pain point / Compliance change / Internal initiative / Leadership request / Tech debt / Other)

PROBLEM STATEMENT
3. Who is experiencing this problem? * (Select all: Customers / Admins / Internal staff / Partners / Support agents / Other)
4. What is the problem or unmet need? *
5. Where/when does this problem occur? (Context, touchpoint, frequency)
6. Why does this matter? * (Impact on user and/or business)

USERS & TASKS
7. What is the user trying to accomplish? * (Their goal)
8. What specific tasks or workflows does the user perform today to achieve this goal?
9. What's broken or frustrating about their current experience?

BUSINESS VALUE
10. What business outcome does this support? (Revenue / Efficiency / Compliance / Retention / Other)
11. Why is this a priority right now?

STAKEHOLDERS
12. Who is the requestor?
13. Who has final decision-making authority?
14. Who else is involved? (PM, eng lead, designers, compliance?)

HYPOTHESES & ASSUMPTIONS
15. What do you believe will happen if we solve this? (Complete: "We believe [outcome] will be achieved if [user] attains [benefit] with [solution]")
16. What must be true for this to work? (Key assumptions)
17. Which assumption, if wrong, would cause this to fail?

SCOPE
18. What must the solution do? * (Must-haves)
19. What would be nice to have but isn't critical?
20. What is explicitly out of scope? *
21. Are there existing features or patterns we should reference?

CONSTRAINTS
22. Accessibility target (WCAG 2.2 AA unless you know otherwise / Also Section 508 or ADA Title II for public-sector work / Not sure). Do any known users rely on assistive technology?
23. Any compliance or regulatory requirements?
24. If rules differ by region: which jurisdictions or markets are in scope?
25. What's the current technology stack? Any technical constraints?
26. Platform requirements? (Web / Mobile / Both / Offline support needed?)
27. When does this need to ship? Any hard deadlines?
28. Any budget or staffing constraints?

RISKS
29. What could go wrong? (Design, technical, adoption, compliance risks)
30. What dependencies exist? What else needs to happen for this to succeed?

SUCCESS
31. How will we know this is "done"? *
32. What metrics will we measure? *
33. What's the current baseline? (Numbers if available)
34. What does success look like? (Target numbers)

CONTEXT
35. Any existing research, data, or user feedback available?
36. Competitors or products that do this well?
37. Has this been tried before? What happened?
38. Links to relevant docs, Jira tickets, Figma files, Slack threads
```
